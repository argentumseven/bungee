No real household data or physical device is used by the test fixtures. The DNS suite explicitly seeds an old-policy fixture for compatibility isolation/erasure; it is not evidence that new managed DNS enrollment is allowed. Browser DNS rows are synthetic saved legacy data.

The emulator attempt uses a dedicated Android 16 AOSP x86_64 virtual device without KVM. Its identity is checked before commands. No physical phone is targeted. Standard host ADB cannot write its fixed home configuration path in this sandbox; a direct ADB protocol client is used only against the owned loopback emulator. Slow software emulation caused early package-install attempts to be rejected while booting, followed by Android system-service restarts/timeouts. Increasing only this emulator's supported watchdog timeout to 600,000 ms did not produce a usable interactive test. An intermediate APK eventually installed and an app task appeared, but local stop, ordinary admin deactivation, corrupted-state recovery, Settings navigation and cold-boot assertions could not be completed. The owned emulator was stopped. These observations are not passed app-runtime tests; the final APK still needs them.

The operator signing helper previously passed with a disposable test key; no production key has been generated/distributed. Device-owner enrollment remains unsupported with any signer. Personal-app signer changes can require uninstall/re-pair and erase Bungee's own local identity/backlog, not the phone's other data.

Remaining lint warnings include synchronous preference persistence (intentional for stop/receipts), translation/KTX suggestions, and an ImplicitSamInstance warning on Context.stopService(Intent). The latter API identifies the service by its explicit component rather than Intent object identity; no listener is being removed. The newer foreground-service fallback type is now gated to Android 14+, with the pre-14 fallback explicitly using NONE. Runtime behavior still requires device checks.

The local-stop failure tests inject exceptions into the coordinator; they do not prove all Android APIs, filesystem failure modes or hardware behavior. Logical history erasure/backups, storage capacity, concurrent exports and restoration still need load/fault testing. No audit, hardware attestation, whole-phone zero-provider traffic or fully quantum-proof product claim is made. Certificate/device/APK signatures remain classical.

The alpha.8 build initially exhausted the cloud workspace disk; only unused Docker build cache was pruned and generated installer archives were moved to temporary storage. Source, persistent volumes and release APKs were preserved. A clean Android build and fresh container build were then used for final validation; the earlier failed build is not counted as a pass.

## Independent review boundaries

[The second review](REVIEW-2026-10-SECOND.md) and [first review](REVIEW-2026-10.md) separate source corrections from outstanding acceptance tests. Current checks do not establish deployment readiness. Publisher-signature enforcement, encrypted snapshot archives, physical GrapheneOS endurance/cold-boot behavior, export field/endurance testing, endpoint-change recovery and accessibility validation remain open. Local snapshots are plaintext root-only tar files; disk encryption must cover both persistent volumes and updater storage. Indefinite server history remains the owner's explicit requested policy.

The supplied review independently reproduced 23 Python tests; its other suites were blocked by missing build/toolchain artifacts. This cloud has the pinned Rust/Go/Android tools from `scripts/setup-cloud.sh` / `scripts/dev-env.sh`; the current API and browser results above were rerun here against a freshly built server/web bundle. The new JDBC dependency is test-only and is not packaged into the Android app. Updated screenshots are generated by the browser suite using synthetic data and local test tiles.

Alpha.10 moves invitation, history and export responsibilities into separate Rust modules. SQLite CSV readers have a five-minute/two-worker bound and can retain WAL state or need temporary grouping space until they finish/cancel. Free storage and actual home/Caddy large-export behavior still need monitoring/field validation. Exported bytes already transmitted cannot be recalled by server erasure. No publisher-signature or backup-encryption implementation is claimed.

The final alpha.10 APK comes from a completed clean debug/release build, lint and 29-test run. A redundant overlapping Gradle run was stopped; its partial outputs are not used as final evidence. Only unused BuildKit cache was pruned for workspace capacity; source, persistent volumes and previously supplied APK artifacts were preserved.
