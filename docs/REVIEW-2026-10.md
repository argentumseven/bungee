# Source review: alpha.9

This is the historical alpha.9 record. The [second review follow-up for alpha.10](REVIEW-2026-10-SECOND.md) covers later fixes, including streamed CSV exports and explicit command consent.

This review covers defects in alpha.8 and their alpha.9 fixes. The tables retain the tests and unresolved checks from that release; current behavior and results are documented in [VALIDATION.md](VALIDATION.md).

## Confirmed defects and changes

| Finding | Assessment and alpha.9 change | Evidence and remaining boundary |
| --- | --- | --- |
| A: GPS after reboot | Confirmed. The old automatic-start path avoided the location foreground-service type and requested no background-location permission. The manifest now declares optional background location. The app explains why it is needed and sends the owner to Android Settings to grant it explicitly. Only a user start from the visible app, or an automatic start with precise **and** background permission, attempts a location foreground service. A restricted start falls back to connection-only operation or an attention notification. | Pure permission/start decision tests and APK/lint checks. **Physical GrapheneOS acceptance is still open.** A server connection never establishes that GPS is collecting. App/device-care reports distinguish missing permission, a required foreground start and OS service restrictions. |
| B: offline storage | Confirmed. A full encrypted preferences blob imposed work proportional to the entire backlog on each change. New fixes are individual AES-256-GCM encrypted SQLite records. A unique observation-time index handles duplicates; incremental transactions insert/evict/acknowledge records and update counters. Only the requested bounded batch is decrypted. | The production transaction logic is tested against a real host SQLite database with JDBC, including a full 10,080-record queue, corruption and injected transaction failures. The small Android SQLite adapter and Android Keystore execution still require device testing. Host timings are **not** phone latency, battery, flash-write or endurance measurements. |
| C: global limiter exhaustion | Confirmed. Caller-chosen device IDs formerly consumed a shared pre-authentication map; a full map rejected even existing identities. Pre-authentication limits now use the actual TCP source. Authenticated device identities are allocated only after signature verification. Administration, device sources, signed identities, enrollment and legacy DNS have separate bounded maps. A full class continues serving existing keys. Counters saturate rather than overflow. | A live regression sends 4,096 fabricated device IDs from one source and then verifies another phone's signed polling/telemetry and administrator reads/login. Rust tests exercise the full-map boundary and expiry. This reduces this specific attack; it is not a general load or denial-of-service guarantee. |
| “Delivered” before receipt | Confirmed status-semantics defect. The dashboard now displays **Offered · awaiting receipt** after selection for an HTTP response. Expired offers remain **Expired · unconfirmed**. | Browser regression covers offered and executed states. The legacy database/API value `delivered` remains for compatibility; it means offered, not proof the body arrived. An execution receipt is a phone-reported outcome, not attestation. |
| Receipt settled on zero-row update | Confirmed. Responses now identify `recorded`, `already_terminal`, `unknown_command`, `not_offered`, `conflicting_terminal`, `invalid_attempt`, `invalid_status`, `expired` or `retention_elapsed`. Only recording a receipt or matching its existing terminal status/result settles it. The phone ignores an ambiguous old-server `settled:true` without acceptance. | Live tests simulate restoration to a pre-poll command state: the receipt remains unresolved, a new poll permits reconciliation, an exact replay settles, a conflicting outcome cannot rewrite the result, and a missing command remains unresolved. The phone's bounded retention still applies; this does not provide indefinite reconciliation. |
| Network events bypass authentication delay | Confirmed. An authentication deadline now acts as a monotonic floor that handovers/flapping cannot advance. Ordinary transport failure still permits a bounded earlier retry. | Deterministic Kotlin tests cover repeated network events throughout the cooldown. The cooldown is process-local; this is not a persistent account lockout. |
| All admin logins counted as Caddy | Confirmed in bundled deployment. Caddy overwrites a dedicated source header with its actual TCP peer. The Rust listener trusts it only with explicit loopback-proxy configuration and a loopback admin bind. Other forwarding headers are not identity. Separate per-source and household aggregate budgets remain, with at most two Argon2 verifications executing concurrently. | Trusted/untrusted/malformed identity unit tests, real Caddy overwrite/source-admission checks, generated-Compose checks, and live proxy-budget regression. Any process controlling the shared host/network namespace is already within the trusted host boundary. |

## Queue migration and privacy

Old encrypted preference queues migrate in a single SQLite transaction with a durable migration marker. The original preferences are removed only after that transaction commits. Reopening after an interrupted preference cleanup cannot import an acknowledged point again. An invalid legacy record or failed transaction leaves the original queue available for diagnosis; no automatic destructive repair is attempted.

Every ciphertext authenticates its observation timestamp as additional authenticated data. Coordinates/accuracy remain encrypted; the observation timestamps, queue count and loss count are SQLite indexing metadata protected by Android's application sandbox and credential-encrypted storage. This is record encryption, not whole-database encryption. The journal uses full SQLite synchronization. Corruption is surfaced without silently deleting records or generating replacement keys as a journal-repair strategy.

The bound remains 10,080 unique unsent observations. At capacity an insertion removes the oldest queued insertion and increments the loss counter in the same transaction. No server history is silently evicted. Disabling GPS persists withdrawal before queue cleanup; failed cleanup cannot authorize uploads. Re-enabling clears any interrupted old queue first. Stopping sharing retains queued data; local recovery remains independent of the database and its encryption keys.

## Important findings still open

| Area | Current boundary / required work |
| --- | --- |
| Physical Android reliability | The permission conflict is corrected in source, but cold boot, first unlock, re-lock, Doze, multiple days offline, storage pressure, app updates and other-VPN coexistence remain unproven on GrapheneOS. Do not treat a build or permission-unit test as evidence of an actual fix received after reboot. |
| Update authenticity | The updater checks registry TLS, fixed repositories, release constraints and immutable digests, but **does not enforce publisher signatures/provenance**. Rollback/health tests do not establish artifact authenticity. A compromised publishing identity remains a compromise path. Signature verification with a defined publisher identity, rotation and offline/recovery policy remains an open security requirement. |
| Host/backup confidentiality | SQLite location columns, service credentials and updater `.tar` snapshots are **not application-encrypted**. Root-only permissions and checksums provide neither disk encryption nor backup encryption. The entire data/snapshot filesystem must be on encrypted storage, and any exported copy needs independent encryption and key recovery. An unlocked/compromised host administrator can read household data. Built-in encrypted snapshot archives remain open work. |
| Administrator authority | One household administrator password controls all paired devices. Passkeys/MFA, individual users, roles and administrator rotation/recovery need design and testing. Source restrictions do not remove this concentration of authority. |
| Reachability | A fixed numeric home endpoint, UDP reachability and functioning home power/router/server remain dependencies. There is no relay, dynamic endpoint-update mechanism or crowdsourced/offline finding network. CGNAT and blocked UDP can prevent contact. Offline storage cannot make unavailable data remotely retrievable. |
| Retention/capacity | Server history has no automatic expiry, as documented in the README. Operators must monitor capacity and define backup expiry. Optional age limits must preserve the separately retained last-known checkpoint and require an explicit future choice. |
| Map coverage | Local operator-supplied raster MBTiles/City MMDB remain necessary for street maps/IP estimates. Missing data falls back to coordinates; screenshots use a labeled synthetic grid. Public tile requests would contradict the current runtime privacy boundary. |
| Large exports | CSV is currently assembled by paginating in the browser. Long, high-density histories can require many requests and substantial browser memory. Server streaming/cancellable exports and load testing remain open. |
| Accessibility | A 390-pixel browser layout test does not establish screen-reader usability, 200%/large-font behavior, contrast compliance or touch-target adequacy. Those checks remain open for both clients. |

## Physical-device acceptance before relying on recovery

Use an expendable personal test phone with a stable APK signer; do not enroll device ownership. Record OS/build, permissions, device settings and actual observation timestamps. Use a local/private test gateway and synthetic data. Preserve Android Settings and the in-app Pairing & recovery button throughout.

1. Start sharing from the visible app with precise location but no background grant. Obtain a real outdoor GPS fix, close the UI, and check timestamped delivery. Reboot; after the **first unlock**, re-lock without opening Bungee. The connection may resume, but the app/dashboard must show GPS needs a foreground start and must not claim a new fix. Open Bungee and explicitly resume GPS; verify a new fix.
2. Grant background location through the explained Android Settings flow and separately opt into restart. Reboot, perform the first unlock, then re-lock without opening Bungee. Verify new GPS observations from the location foreground service. Repeat with the permission denied/revoked and OS background-start/battery restrictions; verify truthful paused state and the manual recovery path. Before first unlock, credential-encrypted keys/data are intentionally unavailable: no check-in or GPS promise is made.
3. Deny UDP/home connectivity for an extended period while moving the phone. Check actual queue growth, timestamps, battery use and insertion latency at the full bound. Reconnect briefly and then stably; verify adaptive catch-up, deduplication and queue-loss accounting. Exercise clock errors and network flapping; authentication rejections must retain the cooldown.
4. Kill the process during journal insertion, migration and receipt handling; restart and compare records/counters. Exercise low storage, corrupt a test record and verify failures preserve evidence. None of those failures may block the independent local stop, Android force-stop, ordinary admin deactivation or uninstall. Measure Android behavior directly; host transaction-failure tests cover only part of this requirement.
5. Interrupt command responses and acknowledgements; compare offered/expired/unconfirmed status with the actual effect. Restore an isolated server snapshot from before polling and replay receipts without repeating phone actions. Verify no expired command becomes executable and no conflicting receipt rewrites a terminal result.
6. Test screen-off/Doze, OS app updates, signer continuity, profile separation, another VPN, home gateway reboot/address change, power loss, storage exhaustion and isolated restore. Inspect network traffic for unintended public destinations. Verify accessibility and both recovery entry points. Record failures and the exact device/build combinations tested.
